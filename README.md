# 问卷星自有测试问卷 · 批量填写工作台

一个本地运行的小工具：给**自己创建、有管理权限的测试问卷**批量造数据，用来验证题目跳转、必填校验、提交流程和答案分布。

题目不用写死在代码里——粘一个问卷链接就自动识别题型和选项；答案的整体倾向用一个滑块控制，还能精确卡每道题的比例。带一个可视化界面，运行中改重心也能立刻生效。

> **用途边界**：仅用于你自己创建、有管理权限的测试问卷。请勿用于他人问卷、刷票、刷量，或影响任何真实调查的统计结果。

---

## 功能

- **自动抓题**：粘问卷链接，识别单选 / 多选 / 填空 / 矩阵量表，保留真实 input id；抓不到可粘贴页面源码
- **重心控制**：`bias` 一个滑块从「偏轻」到「偏重」，`sharpness` 调倾斜陡峭度，界面实时模拟 300 份的答案分布
- **精确配额**：某题设 `ratio` 可严格按比例出答案，不靠概率碰运气
- **热加载**：脚本运行时直接改配置或拖滑块存盘，下一份立即生效
- **并发**：1~4 个浏览器上下文同时填（推荐 3），自动错开提交间隔
- **安全验证自动处理**：问卷星的「需要安全校验，请重新提交！」和阿里云智能验证会自动点掉并重新提交；验证弹窗识别、拟人化点击、失败自动刷新重试、窗口自动关闭，全程无需手动干预
- **拟人化鼠标**：贝塞尔弧线轨迹、随机抖动、不匀速移动、随机点击偏移
- **结果可核对**：逐份答案写进 `wjx_result.csv`，运行日志写 `wjx_run.log`
- **配置体检**：一键校验题目/规则是否失配，列出每题「重心偏重时实际会倾向哪个选项」的确定事实，方向配反一眼看穿
- **自适应节流**：检测到风控提示或验证弹窗时自动降并发、拉长提交间隔、短暂冷却；连续干净成功后逐步恢复
- **零依赖单测**：`unittest` 覆盖抽样、配额、热加载、校验器、题目解析、节流器和开放题复用场景，72 个用例约 1 秒跑完
- **开放题（文本题）**：自动识别 `textarea` / 输入框的真实 id，界面上可逐行配文案池、设留白比例；填不中会明确报错，不静默跳过
- **并发有上限**：界面给出 1~4 档下拉并标注推荐值与依据，上限由实测确定（见下文）

## 快速开始

**环境**：Windows + Python 3.10+，本机装了 Edge 或 Chrome（不用另外下载 Chromium）。

```bash
# 1. 装依赖（只需一次，也可以双击 install.bat）
pip install playwright

# 2. 启动（Windows 双击 start.bat 也行）
python wjx_studio.py

# 3. 浏览器打开 http://127.0.0.1:8765
```

界面里四步：**粘链接 → 抓取题目 → 拖滑块调重心 → 开始批量填写**。
详细步骤见 [操作手册.md](操作手册.md)；项目原理与维护信息见 [项目交接.md](项目交接.md)。

```bash
# 回归测试（零依赖，不需要浏览器）
python -m unittest discover -s tests -v
```

## 目录结构

| 文件 | 作用 |
|---|---|
| `wjx_studio.html` | 可视化界面（单文件，原生 HTML/CSS/JS） |
| `wjx_studio.py` | 本地 HTTP 后端，零第三方依赖，只监听 127.0.0.1:8765 |
| `wjx_autofill.py` | 核心：答案抽样、Playwright 并发填写、验证处理 |
| `validate_profile.py` | 配置体检：静态校验题目/规则失配，输出方向核对事实 |
| `throttle.py` | 自适应节流器：动态并发闸、间隔、冷却与恢复 |
| `tests/` | 零依赖 `unittest` 回归套件（72 个用例） |
| `verify_open_text.py` | 开放题离线自检：喂一份问卷页源码，验证识别/定位/填写，不联网不提交 |
| `answer_profile.json` | **唯一数据源**：问卷链接、题目结构、每题规则、整体重心、运行参数 |
| `start.bat` | 一键启动工作台 |
| `install.bat` | 一键安装 playwright（阿里云镜像，失败给备用源） |
| `操作手册.md` | 面向使用者的逐步操作说明 |
| `项目交接.md` | 面向 AI / 接手者的完整技术交接 |
| `wjx_result.csv` | 运行产物，逐份答案（不入库） |
| `wjx_run.log` | 运行日志（不入库） |

**文件看起来多，其实只有三类是可删的**：`wjx_result.csv`、`wjx_run.log`（每次运行会重写），
以及 `answer_profile.backup.json`（改配置前留的本地备份，已 `.gitignore` 排除）。
其余都是项目必要文件；`.git/` 是版本库、`.workbuddy/` 是工作区数据，都不要删。

## 命令行用法（不想开界面时）

```bash
# 离线预览：不开浏览器、不提交，直接看每题占比和整体倾向值
python wjx_autofill.py --preview --bias 0.6 --total 20

# 正式跑
python wjx_autofill.py --bias 0.8 --total 20 --concurrency 3

# 只填不提交，用来检查选项有没有点中
python wjx_autofill.py --dry-run --total 2
```

| 参数 | 说明 |
|---|---|
| `--bias` | 整体重心 `-1.0`(最轻) ~ `+1.0`(最重)，覆盖配置文件 |
| `--sharpness` | 倾斜强度，0 接近均匀，越大越极端，建议 1~4 |
| `--total` | 提交份数 |
| `--concurrency` | 同时开几个浏览器上下文 |
| `--headless` | 无界面运行 |
| `--dry-run` | 只填不提交 |
| `--no-adaptive` | 关闭自适应节流，回到固定并发 + 固定间隔（A/B 对比用） |
| `--allow-over-limit` | 允许并发超过实测上限 4（仅压测/实验，会打印警告） |
| `--preview` | 离线看分布，不需要 playwright |
| `--profile` | 指定另一个配置文件 |

## 配置说明（`answer_profile.json`）

```jsonc
{
  "url": "https://v.wjx.cn/vm/xxxxxx.aspx",
  "total": 20,              // 提交份数
  "concurrency": 3,         // 并发数
  "headless": false,
  "bias": 0.6,              // 整体重心
  "sharpness": 2.0,         // 倾斜陡峭度
  "questions_meta": {       // 抓取出来的题目结构，勿手改
    "q1": {"title": "您的性别", "kind": "radio", "opts": ["男", "女"], "ids": ["q1_1", "q1_2"]}
  },
  "questions": {            // 每题规则
    "q1": {"mode": "ratio", "ratio": [0.5, 0.5]},
    "q2": {"mode": "trend", "dir": 1, "strength": 1.0},
    "q6": {"mode": "multi", "prob": [0.5, 0.5, 0.5], "min": 1, "max": 3}
  }
}
```

| `mode` | 含义 |
|---|---|
| `trend` | 跟随整体重心；`dir=1` 选项越靠后越重，`dir=-1` 越靠前越重；`strength` 调该题跟随强度 |
| `ratio` | 精确配额，如 `[0, 0, 0.2, 0.3, 0.5]`，**不受 bias 影响** |
| `multi` | 多选题，每个选项独立概率 + 最少/最多选几项 |
| `off` / `uniform` | 不跟随 / 各选项均匀 |
| `text` | 开放题/填空题。`texts` 为文案池（每行一条，每份随机取一条）；`blank_rate` 设留白比例（非必填题）；`follow_bias: true` 才按重心选文案。默认用**中性通用短句**，不会答非所问 |

> 配置里的 `url` 是示例测试问卷，请替换为你自己有权限的问卷链接。

## 运行状态

`wjx_result.csv` 的「状态」列：

| 状态 | 含义 |
|---|---|
| `ok` | 提交成功（以页面跳转到 `completemobile2.aspx` 为准） |
| `ip_blocked` | 被 IP / 频率限制拦下 |
| `need_verify` | 验证超时，需要人工过一次 |
| `no_response` | 页面长时间无响应，已自动跳过这一份 |
| `timeout` | 等待结果超时 |
| `error` / `no_submit_button` | 异常 / 没找到提交按钮 |
| `dry_run` | 只填未提交 |

## 常见问题

**Q：提示缺少 playwright？**
双击 `install.bat`，或 `pip install playwright`。用的是本机 Edge/Chrome，**不需要** `playwright install chromium`。

**Q：抓不到题目？**
点「用源码识别」，把问卷页另存的 HTML 贴进来。或者确认链接是 `https://v.wjx.cn/vm/...` 这类问卷页而不是管理后台。

**Q：多个窗口还是同一个 IP，会不会被拦？**
会。并发上下文共用公网 IP，问卷星可能触发智能验证或频率限制。脚本能自动处理验证；最省事的做法是在问卷设置里关掉「同一 IP 限制」，或降低并发、加大提交间隔。需要彻底隔离 IP 可在 `wjx_autofill.py` 的 `CFG["PROXIES"]` 配代理。

**Q：拖滑块没反应？**
先看该题是不是被设成了 `ratio`（精确配额不受 bias 影响）或 `off`（不跟随）。

**Q：能不能跑别的问卷？**
可以。粘新链接重新抓取一次即可，题目和规则全在 JSON 里，代码不用改。多页 / 跳题逻辑复杂的问卷建议先 `--dry-run` 验证选项是否点中。

## 开放题（最后一题「你的建议」「有什么好想法」）

很多问卷最后一题是自由发挥的文本题。处理方式：

1. **自动识别**：`parse_html()` 遇到没有 radio/checkbox 的题块，标记为 `kind:"text"`，并抓取
   `textarea` / `input[type=text]` 的真实 id 存到 `questions_meta[q].text_ids`。
2. **界面配置**：第 3 步的开放题卡片里有个文本框，**每行写一条**，脚本每份随机取一条；
   「留白比例」控制有几成答卷不填（非必填题才设，默认 0）。
3. **精确定位**：`APPLY_JS` 优先按 `text_ids` 里的 id 找输入框，找不到再退回
   `div.field[topic=N]` 容器，再退回常见 id 命名。**填不中会返回 `0/1` 并在日志里报出来**，不会静默当作填好了。
4. **默认文案中性**：没配文案池时用「暂无 / 无特别建议 / 整体还可以 …」这类通用短句，
   不会冒出别的上文主题相关的句子。想让开放题也跟着重心走，可在 JSON 里加 `"follow_bias": true`。
5. **不影响倾向值**：开放题不参与选项分布，也不计入整体倾向值。

### 复用性（位置无关、数量无关）

- `parse_html()` 按题块独立处理：开放题**可以在任意位置**（第 1 题、中间、最后一题都可以），
  也可以**有多道**。实测 8 题、开放题分别在第 2 / 5 / 8 题的场景，三题全部正确识别并填中。
- 收集 `text_ids` 时排除页面尾部的全局输入框（`matrixinput` / `clipVoteCode` 等）与 readonly 字段，
  并把与题号匹配的 id 排最前。否则开放题恰好在最后一题时，页面尾部的全局元素会被归进它的题块，
  顺序一变就会填到别人的框里。
- 提交前**回读每道开放题输入框的真实 value**，写进 `wjx_result.csv` 备注
  （`开放题实际填写: q8='...'`），可直接与问卷后台逐份核对。
- 已用改过的真实问卷（8 题，最后一题为开放题）实测：`text_ids=['q8']`、离线自检填中、
  真跑 2/2 + 1/1 提交成功，CSV 备注能看到实际填入的文本。
- **当前限制**：同一题块里有多个输入框（如「姓名 + 建议」）时只填第一个；
  多道开放题各自有输入框则完全支持。

> 已在**模拟问卷星结构的真实浏览器 DOM** 上验证（精确 id、题号兜底、找不到报错、
> 留白不被兜底覆盖、验证码框不受影响）。**不需要提供问卷链接也能自查**：

```bash
# 浏览器打开问卷页 → 右键「查看网页源代码」→ 另存为 page.html
python verify_open_text.py --html page.html --text "建议增加午休时间"
```

脚本严格离线（拦截所有外部请求）、不提交任何问卷，会输出识别到几道开放题、
`text_ids` 有没有抓到、体检结果，以及每道题在真实浏览器 DOM 里是否填中并回读一致。
抓公开问卷的源码来验证解析也可以——只解析、不提交，不越界。

**唯一仍需人工确认的**是「服务端有没有收到这段文本」：在自己有权限的测试问卷里
加一道选填开放题，真跑 1 份后去后台看一眼即可，不需要把链接交给任何人。

## 为什么「同时运行几个」最大是 4

**结论：上限 4，推荐 3。** 这不是浏览器开不了更多，而是**同一个公网 IP 的风控**决定的。

梯度压测（每档 5~6 份，默认开自适应节流）：

| 并发 | 成功 | 验证触发 | 自适应降速 | 结束时有效并发 | 单份均值 |
|---|---|---|---|---|---|
| 4 | 6/6 | 6 次 | 6 次 | 1 | 11.2s |
| 6 | 6/6 | 5 次 | 5 次 | 1 | 13.0s |
| 8 | 6/6 | 4 次 | 4 次 | 4 | 15.0s |

三个约束：

1. **技术上限远高于 4**：8 个浏览器上下文能同时跑通、全部提交成功，本机没有 OOM 或崩溃。
2. **决定性约束是同 IP 提交密度**：所有窗口共用一个出口 IP，并发越高、单位时间提交越密，
   问卷星/阿里云越容易要求安全验证。并发 ≥4 时几乎每份必现验证，自适应节流会把
   **实际有效并发压回 1~4**，设定 6/8 只是名义值，却要多付验证与降速的开销。
   冷 IP 下并发 3 的基线是单份约 3.5~4.5 秒；高并发档涨到 11~15 秒，**边际收益为负**。
3. **IP 热度是更大的变量**：压测后段连并发 1 也高频触发验证，说明连续几十份提交后
   出口 IP 已进入高风险状态。因此调并发数不如**关掉问卷的 IP 限制/智能验证**或**配代理池**有效。

所以界面把可选范围收敛到 **1~4（推荐 3）**，并在下拉下方直接写明原因；
`validate_profile.py` 里的 `MAX_CONCURRENCY` 是单一数据源：界面下拉、后端校验、体检提示、**命令行 `--concurrency` 和配置文件**都通过 `resolve_concurrency()` 收敛到它；只有显式 `--allow-over-limit` 才能超限（压测复现用）。

短批（5~6 份）里降速后往往来不及恢复（连续 5 份干净成功才恢复一档），长批会逐步恢复，
所以高并发尤其不适合小批量测试。
